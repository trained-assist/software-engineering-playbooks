## Челлендж 🔴/⚫

**🔴 нет.** Плейбук — шаблон в библиотеке: не трогает права, аутентификацию, биллинг, миграции данных, мульти-тенантность. ssh-доступ и деплой-механизмы уже существуют и в этой задаче не меняются.

**⚫-кандидат (снят): «staging обязателен до мержа, а в скилах search/speech staging-job отсутствует».**
- Цена без разрешения: ветка поведения шага «PR» для каждого скила → риск тихого skip или вечного ожидания; типичные баги — мерж без staging (прямо запрещён правилом) либо зависший план.
- Разрешение: правило 2026-09-16 уже задаёт поведение — «отсутствие staging блокирует мерж». В шаге PR ставим детерминированный чек наличия staging-job в CI целевого скила: job есть → гейт `ci_and_staging_green`; job нет → шаг блокируется и вешает владельцу задачу «добавить staging-gate в CI скила» (пробел ведём в issue #9), а не пропускает молча.
- Дешёвая альтернатива получена: +1 grep-проверка на шаге, без новых валидаторов core и без правки рантайма плейбуков.

## Принятые решения

1. Staging-развилка разрешена чеком на шаге (см. ⚫ выше), не развилкой архитектуры — шаг propose-change описывает обе ветки явно.
2. Шаг «релиз» обязан указывать запасной путь проверки на случай снятия ssh-доступа (#1818), иначе гейт станет невыполнимым для всех.
3. Пробный прогон — только read-only тул; выбор скила и тула — на шаге пробного прогона, до дизайна не блокирует.
