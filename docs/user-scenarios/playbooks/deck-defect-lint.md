# Сценарий: дефекты слайдов находит генератор, а не глаза

Трекинг: https://github.com/trained-assist/trained-assist-documents-skill/issues/8 (закрыт 2026-10-02),
сопутствующий: https://github.com/trained-assist/trained-assist-documents-skill/issues/9 (мёртвая копия
генератора, открыт). Код и контракт живут в `trained-assist/trained-assist-documents-skill`
(`src/deck/defects.js`, `src/deck/deckgen.js`, `src/deck/render-smoke.js`), этот файл описывает
поведение, а не историю изменений.

## Актор и ценность

Актор: агент-исполнитель плейбука `presentation-creation` (или владелец вручную), который готовит колоду
и должен отдать её без переполнений и наложений текста.

Ценность: агент получает измеримый сигнал «текст не влезает» по каждому блоку и по каждому слайду
вместе с оценкой 0–100, поэтому цикл правки текста закрывается автоматически, а колода уходит
в delivery без битых заголовков.

Негативная ценность (тоже должна держаться): агент НЕ получает ложных срабатываний на нормальных
слайдах и НЕ тратит цикл на «проверку глазами» — advisory-классы не роняют гейты и не мешают доставке.

## Доказанность ценности: V5

Источник: живая проверка на четырёх боевых колодах проекта (2026-10-02). До фикса все четыре давали
`warnings: 0` при реальном переполнении заголовков на 38pt и наложении текста на 10pt — то есть обходной
путь «отдать как есть и надеяться» был единственным, и он не работал. Обнаружено браузером
(`scrollHeight > clientHeight`, попарные пересечения прямоугольников), не на глаз.

## Что уже есть (переиспользуем, не пишем заново)

- `src/deck/deckgen.js` — генератор: раскладка, `fit()` по типам блоков, единая точка проверки высоты
  текста в обёртке `txt()` на месте всех вызовов `sl.txt`.
- `src/deck/defects.js` — контракт дефекта, `pushWarning`/`pushDefect`, скоринг, `DECKGEN_VERSION`.
- `src/deck/render-smoke.js` — наземная правда в Chromium + сверка с оценщиком.
- `src/mcp-skills/tools/10-deck.js` — MCP-обёртки `deck_check` / `deck_render` / `deck_markup_guide`.
- `playbooks/presentation-creation.json` — цикл render + fit, два гейта, читающих `warnings`.
- Песочница `scripts/sandbox/deck-defect-lint.sh` (`npm run sandbox:deck-lint`) — замкнутый цикл
  «исходник → рендер → дефекты → правка → чисто» одной командой, 12 проверок.

## Шаги (КОГДА → ТОГДА)

1. **Отчёт.** КОГДА агент зовёт MCP `deck_check` (или `node src/deck/deckgen.js deck.md --report r.json`)
   ТОГДА отчёт содержит `{slides, warnings: string[], defects[], score}`, у каждого дефекта —
   `level` 1–5, `code`, `slide`, `block`, `detail`, `measured_pt`, `source`, плюс `deckgen.version`.
2. **L1 без браузера.** КОГДА текст не влезает в бокс любого типа (`lead`/`bullets`/`callout`/`cards`/
   `flow`/`quote`/`title`) ТОГДА появляется строка в `warnings[]` («текст не влезает на Npt») И запись
   `l1_box_overflow` в `defects[]`; допуск 2pt, иначе мелкий антиквазинг давал бы ложные срабатывания.
3. **L1 на земле.** КОГДА оценщик и Chromium расходятся ТОГДА в отчёт падает `l1_estimator_false_positive`
   или `l1_estimator_false_negative` — дефект инструмента, в `warnings` он НЕ идёт и гейты не роняет.
   Наложение строк, найденное браузером, — `l1_text_overlap`.
4. **L2 двойной маркер.** КОГДА пункт исходника начинается с `✓`/`•`/`[x]` ТОГДА `l2_double_marker`
   с инстансом; при запуске с `--autofix-markers` лишний маркер снимается (`- ✓ пункт` → `пункт`),
   без флага текст не меняется; `✓` в середине предложения не флагуется.
5. **L2 бюджет выделений.** КОГДА в блоке больше двух приёмов выделения (`**`/`*`/`***`/цвет) ТОГДА
   `l2_emphasis_budget`; блоки кода с подсветкой и цвет самого блока не считаются.
6. **L4.** КОГДА интерлиньяж вне 1.2–1.6 ТОГДА `l4_leading`; иерархия заголовок/подзаголовок слабее 1.3 —
   `l4_hierarchy`; рассогласованные левые края колонок списка — `l4_column_alignment`.
7. **L5 близость.** КОГДА нижний блок колонки ближе к футеру, чем к своему смысловому блоку ТОГДА
   `l5_proximity` с измеренными зазорами; на титулах/разделителях и при одной группе блоков не считается,
   допуск 8pt.
8. **Скоринг.** КОГДА дефекты собраны ТОГДА `score.deck` = 100 − Σштрафов `{1:100, 2:25, 3:8, 4:3, 5:1}`,
   `maxLevel`, `verdict` (`clean`/`advisory`/`warn`/`critical`) и `counts`; `score.perSlide` — то же по слайдам.
9. **Каналы.** КОГДА дефект уровня 1, 3 или 4 ТОГДА он попадает и в `warnings[]` (строковый контракт, который
   читают гейты плейбука, `--strict` и MCP), а уровни 2–5 остаются только в `defects[]` — advisory.
10. **Правка → чисто.** КОГДА агент переписывает текст, помеченный дефектом, и перезапускает проверку
    ТОГДА `warnings` пустеет, а вместе с ними и L1; L5 текстом не лечится (нужен порядок блоков) и остаётся
    advisory.
11. **Гейты.** КОГДА плейбук проверяет `presentation-*.deckgen.json` ТОГДА ненулевой `warnings` даёт
    ненулевой выход, advisory-дефекты — нулевой: гейт честен в обе стороны.
12. **Версия генератора.** КОГДА отчёт прочитан ТОГДА `deckgen.version` позволяет отличить этот генератор
    от любой другой копии `deckgen.js` на машине (см. documents-skill#9).

## Крайние случаи

- Chromium недоступен → `render-smoke` падает с внятным текстом, а не скипается молча; уровни 2–5
  и оценщик L1 работают без него.
- Пустая колода / блок без текста → дефектов нет, оценка 100, `verdict: clean`.
- Мелкое переполнение ≤ 2pt (антиквазинг, разные метрики шрифта) → не дефект.
- Титул/разделитель/одноколоночный слайд → L5 не считается.
- Блок во всю высоту колонки → L5 не флагуется (иначе ловится сам собой).
- Расхождение оценщика и браузера → громкий дефект инструмента, а не тишина.
- Повторный прогон без правок → тот же отчёт, байт-в-байт (детерминированно, без браузера).
- Старая копия генератора вне репозитория может вернуть пустые `warnings` — на это отвечает
  `deckgen.version` в отчёте.

## Не-цели

- Менять вёрстку: это линтер, дефекты измеряются и докладываются, авто-правка текста — только
  двойной маркер и только opt-in.
- Расширять `warnings[]` типами или структурой: тип `string[]` читают гейты плейбука, `--strict` и MCP.
- Текстовые правки по советам L5: нужен порядок блоков, это работа автора слайда.
- Правка текста плейбука `presentation-creation.json` под advisory-дефекты: гейтами они не проверяются.

## Приёмка (исполняемая)

- `npm test` — 65 тестов, включая по фикстуре на каждый тип блока для L1 и по одному на каждый класс L2/L4/L5.
- `npm run sandbox:deck-lint` — 12/12 GREEN (замкнутый цикл, повторяющий сценарий).
- `npm run check` + core MCP conformance в CI — контракты MCP не сломаны.
- Наземная правда: на колодах проекта `l1_estimator_*` не показывает расхождений оценщика с браузером
  на L1 (2026-10-02: B-en 2 = 2, 0 ложных/пропущенных).
- Живая проверка: переполнение, найденное на B-en (38pt), подтверждено браузером и снимается правкой текста.

## Открытые вопросы / риски (закрыты допущениями, без вопроса владельцу)

- Где живут уровни: `warnings[]` остался строковым контрактом (его читают гейты, `--strict`, MCP),
  уровни и оценка — в новых `defects[]`/`score`; L1 дублируется в оба канала, иначе гейты продолжили бы
  пропускать битые слайды.
- «Смысловой блок» для L5: опорный блок = предыдущий блок той же колонки раскладки; на титулах,
  разделителях и при одной группе блоков проверка выключена — там были ложные срабатывания.
- Ложные срабатывания L1 как главный риск: сняты допуском 2pt и обязательной сверкой с браузером;
  откат — revert аддитивного коммита, вёрстка не затронута.
- L1 «пропуск оценщика» на +2pt (A-ru, слайд 15, callout) помечен как `l1_estimator_false_negative`:
  дефект инструмента виден, гейты не падают.
