## Челлендж ⚫ R9: прод-вердикт для не-agent репо

**Три взаимоисключающих варианта в самих входных материалах** (текст сценария противоречит сам себе):

1. *Предусловия сценария*: «для прочих репо — итог последнего deploy-workflow на `main` c SHA мерж-коммита либо `unknown`» → deploy-джоб определяет вердикт.
2. *П.3 сценария*: «зелёный deploy-джоб без health — `unknown`/`deploy_green`, не `live`» → deploy-джоб НИКОГДА не даёт `live`.
3. *Контекст (шаг 2)*: для скиллов — «`unverified` + эвристика «деплой агента после `merged_at`»» → третья модель.

Один и тот же вызов на репо без health даёт три разных ответа в зависимости от того, какой абзац читать. Это и есть ⚫.

**Что разные модели означают по факту:**

- `trained-assist-agent` → `commit` в `GET /agent/health` + `compare` на предка → **точно**.
- `tg-bot` / `web` (Cloudflare) → health с sha нет; деплой = wrangler-deploy-джоб → deploy-успех ≈ деплой случился, но проверить, что отдаёт прод, нечем.
- доменные скилы и этот репо → деплоя нет вовсе (`scripts/deploy.sh` подтягивает их лишь при деплое агента, `/health` их sha не отдаёт) → единственный сигнал «деплой агента позже `merged_at`» → эвристика.

**Цена, если в прод идёт вариант 1 (deploy-джоб → `live`):** это прямо противоречит заявленной негативной ценности сценария («агент НЕ получил ложное „доехало до прода“ по зелёному деплой-джобу»). Ветка «вердикт из deploy-job» даёт `live`, когда деплой завершился, но агенту проверить отдачу нечем → ложное «в проде», тот самый класс ошибки agent-notes 11.09. Вариант 3 (merged_at-эвристика) плодит ещё одну ветку с ложными `not_yet` (деплой мог идти до мержа).

**Решение (снято без вопроса — снят безопасный вариант, единственный дорогой вариант противоречит обещанию сценария):**

- `prod.verdict:"live"` выдаётся **только** из health-compare (сейчас — только `trained-assist-agent`). `not_yet` — тоже оттуда.
- Всё остальное → `prod.verdict:"unknown"`, а deploy-джоб / отсутствие эндпоинта / `merged_at` уходят в `prod.evidence` (`deploy-green`, `no-prod-endpoint`) и в `prod.source`, **никогда в verdict**.
- merged_at-эвристика как вердикт — не реализуем.
- Точность для скиллов даёт отдельный PR в агенте (sha сиблингов в `/health`) — уже в открытых вопросах.

**Цена решения, которую видит владелец:** CF-репо (`tg-bot`, `web`) и доменные скиллы всегда отвечают `unknown`, хотя деплой по факту мог пройти — осознанная потеря информации ради нулевой вероятности ложного «live». Если владелец захочет для CF считать успешный deploy-джоб `live` с явным `source:"deploy-job"` — это отдельное, дешёвое расширение в том же PR.
