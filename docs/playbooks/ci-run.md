# Плейбук `ci-run` — Прогон тестов ветки в облаке

> Сгенерировано `scripts/build-playbooks.js` из `playbooks-src/ci-run.json` и `library/step-types.json`. Правь источники, не этот файл.

**Когда:** Нужен ответ по тестам ветки (до открытия PR или вместо большого локального прогона), а в репозитории уже есть ручной запуск тестов. Если его нет — сначала ci-setup.

**Результат:** Ответ по тестам ветки получен из облака: зелёные/красные, упавшие тесты и хвост лога — без локального прогона.

- Весь обмен с GitHub — одним MCP-тулом ci_run_branch: без run_id он диспатчит прогон и возвращает свой run_id, с run_id он читает статус, упавшие джобы и хвост лога. Другие вызовы к Actions API от руки не пиши.
- Ожидание — только через task_item_wait с условием ci_run_green и финальной строкой DURABLE: waiting. Busy-wait (цикл с sleep внутри рана) запрещён: он держит слот и жжёт токены.
- Прогон ничего не сливает и не выкатывает — это диспатч и чтение. Если в репозитории есть деплой-джобы, они на этот запуск не реагируют (свой workflow, свои триггеры).
- Если репозиторий не настроен — предложи плейбук ci-setup и остановись. Молча настраивать чужой репозиторий этим плейбуком нельзя.

**Запуск:** `playbook_run(playbook_id: "ci-run", goal: "<что делаем>", vars: {repo: "<owner/repo>"})` → черновик плана → `task_update(status: "active")`.

## Шаги подробно

### Стадия «Диспатч, ожидание, результат»

#### 1. Прогнать тесты ветки в облаке и вернуть результат

```text
Тип шага: ci-run — Ответ по тестам без локального прогона: диспатч в GitHub Actions, дешёвое ожидание, упавшие джобы и хвост лога.

Репозиторий: {repo} (если вместо имени репозитория тут слово repo в фигурных скобках — его не передали в playbook_run: определи из цели и итогов прошлых шагов или спроси пользователя).

Чек-лист (пройди все пункты за этот ран; в ИТОГЕ ШАГА коротко отметь каждый: ✅ сделано / ⏭ не нужно — почему):
1. Повторный ран этого шага НЕ диспатчи заново: возьми run_id из evidence прошлого рана и сразу перейди к проверке статуса.
2. Диспатч: ci_run_branch(repo: "{repo}", ref: <ветка>[, suite: <набор>]) → {ok:true, run_id, url}. Репозиторий без ручного запуска ответит {ok:false, configured:false} — сообщи это и ПРЕДЛОЖИ плейбук ci-setup (не запускай его молча); если ответ нужен прямо сейчас, набор можно прогнать локально и сказать об этом явно.
3. Дождись без зависания внутри рана: task_item_wait(until: {ci_run_green: {repo: "{repo}", run_id: <id>}}, poll_every_sec: 120, timeout_sec: 3600, reason: "ждём прогон тестов ветки") → DURABLE: waiting. Сервер проверяет условие дёшево сам.
4. Проснулся → ci_run_branch(repo: "{repo}", run_id: <id>) в статус-режиме. conclusion success → «зелёный»: ветка, длительность, url.
5. conclusion failure → «красный»: перечисли failed_jobs и покажи log_tail (хвост лога упавшей джобы, там видно имя упавшего теста); чини новой веткой/коммитом по правилам репо, новый прогон — новым вызовом.
6. cancelled / skipped / timed_out → это НЕ зелёный: напиши причину явно («run cancelled») и разберись, кто отменил прогон.
7. В итоге — одна строка вида «Тесты <ветка>: ЗЕЛЁНЫЕ — <url>» или «Тесты <ветка>: КРАСНЫЕ — <url>, упал <тест>».

Готово, когда: Ветка прогнана в облаке: в ответе статус (зелёные/красные) и url рана, а для красного — упавшие джобы и хвост лога; ненастроенный репозиторий помечен явно с предложением ci-setup.

Для этого плейбука:
- Если ветка ещё не запушена — сначала git push -u origin <ветка>: диспатч без коммитов на сервере прогнать нечего.
- run_id после диспатча запиши в evidence шага, иначе повторный ран задиспатчит прогон второй раз.

Общее для плейбука «ci-run»:
- Весь обмен с GitHub — одним MCP-тулом ci_run_branch: без run_id он диспатчит прогон и возвращает свой run_id, с run_id он читает статус, упавшие джобы и хвост лога. Другие вызовы к Actions API от руки не пиши.
- Ожидание — только через task_item_wait с условием ci_run_green и финальной строкой DURABLE: waiting. Busy-wait (цикл с sleep внутри рана) запрещён: он держит слот и жжёт токены.
- Прогон ничего не сливает и не выкатывает — это диспатч и чтение. Если в репозитории есть деплой-джобы, они на этот запуск не реагируют (свой workflow, свои триггеры).
- Если репозиторий не настроен — предложи плейбук ci-setup и остановись. Молча настраивать чужой репозиторий этим плейбуком нельзя.
```
