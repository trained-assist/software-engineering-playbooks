# 2026-10-09 — перенос генерации ТЗ из freelance-skill в engineering (issue #43, план b86456ed)

Выжимка решений и граблей по переносу генерации ТЗ (Директивы 2.В / 3, голос 28.09.2026).
PR: #44 (этот репозиторий, мерж a5e39a9) + вынос из freelance-скила (trained-assist-freelance-skill PR #28).

## Решения

- **Содержание и стиль — разные слои.** Инженерная конкретика (инфраструктура, тестовый сервер, протоколы,
  шаги) и sandbox-блок «как запускается и как проверяется» живут в `CONTENT_RULES`/`SBD_*` и применяются к
  КАЖДОМУ варианту (long и short); стиль — отдельный параметр `style: 'oldschool' | 'modern'`, default =
  новый олдскульный. Так содержательное требование нельзя «выключить», поменяв формулировку документа.
- **Правила — в коде, не в переписке.** Канонические строки правил зафиксированы в
  `src/spec-generation/rules.js` и ловятся детерминированным тестом `tests/spec-generation-rules.test.js`
  (по выводу, как у прежнего `buildSpecInstruction`), песочница `scripts/sandbox/spec-generation.mjs`.
- **Один репозиторий = одна правда.** Генерация ТЗ и движок сложности теперь соседи: оценка сложности
  ВТОРИЧНА (секция «Стоимость и сроки»), движок не дублируется; точка интеграции описана в
  `docs/spec-generation-migration.md`.
- **Кросс-репо переход закрыт чисто.** После мержа инженерного PR отдельным PR удалены из freelance-скила
  `freelance_generate_*`/`SPEC_VOICE_RULES`/`buildSpecInstruction`/e2e, риск-движок и пайплайн проектов не
  тронуты; проверка «остались ли ссылки» — grep по живому релизу, 0 совпадений.

## Грабли

- **Мерж ≠ живой прод.** Проверка слоя A на 28.09 прошла на релизе `e4aa1e2`, но последующий перепрогон
  (шаг 14) нашёл блокер #1963 уже на другом релизе — фикс уехал отдельным PR #2022 в ядро. Урок: контракт
  каталога проверять на живом релизе ПОСЛЕ каждого деплоя ядра, а не один раз «на момент мержа».
- **Архивация спустя дни: ветка плана содержит squash-мерж.** После squash PR #44 ветка плана выглядит
  «не в main» (`merge-base --is-ancestor` → false), а origin/main уехал на несколько PR. Лечится
  `git reset --hard origin/main` (содержимое уже в main) или merge origin/main перед новым коммитом.
- **Продовая проверка была ограничена из слота**: journalctl из рана недоступен (нет прав на VM) —
  компенсировано health-эндпоинтом + поиском ошибок в traces; лимит рана задокументирован в
  `artifacts/prod-check/spec-migration-observation-2026-10-09.md` (папка плана).
- **Быстрый e2e-ловушка**: `test:e2e` в .mjs падал на `require()` до любой проверки окружения
  (`node --check` это не ловит) — переведён на import; правило: ранний fail по отсутствию окружения должен
  быть явным SKIP, а не stack trace.

## Что осталось (помечено в docs, не в этом PR)

- Этап 2: спецификация глубже в инженерную тему (ТЗ для себя при планировании, ideation «5 направлений →
  выбрать оптимальный»).
- Сейлз-форма: отдельная операция «любой документ → более сейлзовый вид», в генератор не встраивать.
