# Изменение: дефекты слайдов 1–5 в deckgen — линтер вместо пустых warnings

Дата: 2026-10-02 · план 77dff113 · трекинг `trained-assist-documents-skill` issue #8 · код и контракт —
`trained-assist-documents-skill` (`src/deck/defects.js`, `src/deck/deckgen.js`, `src/deck/render-smoke.js`),
PR #11 (замена #10), main `b728207`, живой чекаут `/home/vova/trained-assist-documents-skill`.
Живой сценарий: [`docs/user-scenarios/playbooks/deck-defect-lint.md`](../user-scenarios/playbooks/deck-defect-lint.md).

## Что сделано

- `src/deck/defects.js`: контракт дефекта `{level 1–5, code, slide, block, detail, measured_pt, source}`,
  `pushWarning`/`pushDefect`, скоринг `100 − Σ{1:100, 2:25, 3:8, 4:3, 5:1}` с `verdict`
  `clean|advisory|warn|critical`, `DECKGEN_VERSION`.
- L1 переполнение/наложение: единственная точка проверки — обёртка `txt()` на месте всех 17 вызовов
  `sl.txt`, поэтому ни один тип блока (`lead`/`bullets`/`callout`/`cards`/`flow`/`quote`/`title`) не уходит
  непроверенным; допуск 2pt.
- L2 двойной маркер (`✓`/`•`/`[x]` в начале пункта) с opt-in авто-чисткой `--autofix-markers` (off) и
  бюджет выделений ≤2 приёмов на блок; L4 интерлиньяж/иерархия/выравнивание колонок; L5 близость к футеру
  по геометрии колонок раскладки (допуск 8pt, на титулах/разделителях/одной группе выключено).
- Шесть существовавших предупреждений получили уровни 1/3/4, не меняя строки (гейты плейбука и `--strict`
  читают их как раньше).
- `src/deck/render-smoke.js` — наземная правда в Chromium (`scrollHeight > clientHeight + 2`, попарные
  пересечения прямоугольников) + сверка с оценщиком; расхождение = `l1_estimator_false_positive/negative`,
  в `warnings` не идёт.
- `deckgen.version` в отчёте; песочница `npm run sandbox:deck-lint` (12 проверок), шаг Chromium в `ci.yml`,
  документация (README, `deckgen-markdown-format.md`, описания MCP-тулов).

## Решения (и почему такие)

- **Уровни — в новом `defects[]`, `warnings[]` остался `string[]`.** Его читают гейты `presentation-creation.json`,
  `--strict` (exit 2) и MCP-обёртка. L1 дублируется в оба канала: если бы только в `defects[]`, гейты
  продолжили бы пропускать битые слайды — ради этого всё и затевалось. L2/L4/L5 — только advisory, гейты
  не трогают.
- **Смысловой блок для L5** — предыдущий блок той же колонки раскладки, а не «последний блок слайда»:
  на титулах/разделителях и при одной группе проверка выключена (там были ложные срабатывания).
- **Одна точка проверки вместо проверки по типам блоков.** Требование звучало как «расширить `textHeight()`
  на все типы блоков»; структурное решение (обёртка на месте всех вызовов) даёт то же и не даёт
  забыть новый тип блока в будущем.
- **Vёрстка не менялась.** Это линтер: он меряет и докладывает. Единственная авто-правка — снятие двойного
  маркера, и только за флагом, потому что осмысленный `✓` без флага был бы съеден.
- **Текст плейбука `presentation-creation.json` не правили.** Advisory-классы гейтами не проверяются;
  менять инструкции агенту в чужом репозитории без измеримой пользы — лишний риск. Возврат к вопросу:
  если после мержа L2 начнут массово переписывать вручную.

## Что узнали (грабли)

- **Плейбук зовёт не репозиторий, а мёртвую копию.** `presentation-creation` вызывает
  `/home/vova/tools/deckgen/deckgen.js` — копию, отставшую на 262 строки, без `--strict`/`--report`.
  Фикс в репозитории до плейбука не доедет. Открыт documents-skill#9; в отчёте добавлен
  `deckgen.version`, чтобы копия себя выдавала.
- **«CI красный» ≠ «падают тесты».** Прогоны завершались за 0 с без единого job'а, потому что workflow
  не стартовал: незакавыченное `name: Sandbox: lint …` — двоеточие с пробелом делает YAML невалидным,
  и загрузка workflow падает раньше, чем появятся джобы. Локально всё зелёное. Фикс — одна кавычка
  в `.github/workflows/ci.yml`; PR неизменяем → новый PR #11, #10 закрыт как superseded.
- **Chromium падает «Socket path too long» при длинном `TMPDIR`** (> ~108 символов). В слотах агента
  `os.tmpdir()` длинный, в CI `/tmp` короткий — баг виден только на VM. Правило: любой новый тест или
  скрипт с Chromium обязан сам уводить `TMPDIR` в короткий каталог (сделано в `tests/render-smoke.test.js`
  и в песочнице).
- **«Мёртвая копия `deckgen.js`» — не только про playbooks.** Правка в живом чекауте скила этого не
  доказывает: MCP-сервер стартует из `/home/vova/agent-releases/<sibling>`, у этого скила своего
  деплой-workflow нет, а `deploy.sh` ядра синхронизирует только hh-skill и engineering. Проверять надо
  `git log` в том пути, откуда реально стартует сервер.
- **`tools` MCP-скила ≠ тулы в сессии.** Правило реестра прячет модули по секциям профиля:
  `/home/vova/users/<profile>/.skills-resolved.json` → `hidden.modules`. В этой профиле секция
  `documents` не была включена, поэтому `deck_check`/`deck_render`/`deck_markup_guide`/`doc_export`
  были недоступны, хотя персонал-промпт их документирует (см. ниже).

- Проверка сценария в реальном окружении делалась не через тул, а вызовом тех же обработчиков MCP

  отсутствовал. Дальше закрыто включением секции в профиле.
- `deckgen.version` в отчёте — дешёвая страховка от выдачи чужой копии генератора за нашу.
