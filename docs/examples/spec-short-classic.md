# ТЗ: учёт заявок на ремонт для сети автосервисов (short)

Статус: образец нового стиля (oldschool). Контекст — `scripts/sandbox/fixtures/context/`.

## 1. Проблема

Заявка на ремонт живёт в почте и в чате мастера, единого учёта нет, диспетчера трёх филиалов не видят общую очередь.

## 2. Объём

- Приём заявки из веб-формы и мобильного кабинета мастера.
- Назначение заявки филиалу, история статусов.
- Авторизация через существующий Active Directory (LDAP), без новых логинов.
- Общая очередь диспетчера в реальном времени и уведомление о новой заявке.

## 3. Что получаем

Бэкенд на Node.js (HTTP/REST, порт 8080), PostgreSQL 16 для заявок, Redis 7 как очередь уведомлений и канал событий, отдельный воркер, который читает очередь и шлёт уведомления. Интерфейсы — SPA кабинета диспетчера и PWA кабинета мастера. Развёртывание — Docker Compose в контуре заказчика, данные только на серверах в РФ.

## 4. Сроки и приёмка

Пиковая нагрузка — 300 заявок в час, круглосуточно. Приёмка: заявка из PWA появляется в очереди диспетчера не пиком чем через 2 с, вход по AD работает, прогон 300 заявок в час проходит без ошибок.

## 5. Как проверяем

`docker compose up -d && npm ci && npm run migrate && npm run seed && npm run smoke` — смоук поднимает стенд на `localhost:8080`, создаёт заявку, ждёт уведомление воркера и проверяет очередь; зелёный прогон = проверка пройдена.
