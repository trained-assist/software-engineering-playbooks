# repo_map (#49) — proposal / design / срезы / проверка / откат (шаг propose-change)

Входы: сценарий [../user-scenarios/engineering/repo-map-fast-discovery.md](../user-scenarios/engineering/repo-map-fast-discovery.md),
контекст [context.md](context.md), флаги [requirements-flags.md](requirements-flags.md).

## 1. Proposal

**Зачем.** Агент на шагах локализации тратит ~480 ручных поисков (`sed`/`grep`) за 10 дней, чтобы найти,
где что лежит. Один вызов `repo_map(repo, level)` (< 1 с из кеша) даёт сжатую карту репозитория
(≤ 2k токенов L0 / 5–15k L1) — те же файлы находятся с точностью не хуже, discovery-вызовов минимум на 50 % меньше.

**Что меняется.**
- Новый модуль `src/repo-map/` (кеш по sha, рендер L0/L1, LLM-описания) поверх существующего индекса `src/index/*`.
- Новый MCP-тул `repo_map(repo, level, focus)` в `src/mcp-skills/tools/35-repo-map.js`.
- Хранилище производных данных (индекс + карты) переезжает из дерева worktree в общий кеш профиля по sha —
  рабочие копии одного коммита делят кеш, worktree не пачкается.
- Хук сборки при spawn (фоном, спавн не ждёт) + ленивая достройка при обращении к новому sha main.
- Правило «сначала repo_map L0 → L1 focus → чтение» в плейбуках feature/debugging и `src/prompt-domains/engineering.md`.

**Влияние.**
- Модули: `src/index/*` (путь хранения), `src/workspace/*` (хук после spawn), `src/mcp-skills/tools/*` (+1 тул),
  `src/context-sources/indexed-repo.js`, `src/prepare-task.js` (резолв нового пути — один шов).
- Контракты: схема индекса v1 → layout v2 (путь), новый тул в `provider-manifest.json` + conformance «никогда пусто».
- Данные: только производный кеш (индексы/карты); ничего пользовательского, миграция не нужна — старые
  индексы в `.engineering/index` просто игнорируются.
- Другие сервисы: не затронуты (тул добавляется, ничего не заменяет).

## 2. Design — наименьшее изменение

**Стек решений (в т.ч. по открытым вопросам context.md):**
- Парсер JS/TS: **вендор `acorn`** (`vendor/acorn/acorn.js` + LICENSE, UMD, require без node_modules) для JS;
  для TS/Python/MD/прочих — улучшенный regex-скан (`src/index/lang.js`, чиним пробел CJS
  `module.exports = {a,b}` и методы). Почему не `typescript`+npm ci в deploy.sh ядра: второй репозиторий
  и изменение выкладки ради одного рендера; почему не tree-sitter: нативная сборка на VM.
- Хранилище: `<workspacesRoot>/repo-maps/<repoId>/<sha>/{index/,map-l0.json,map-l1.json,descriptions.json,lock}`
  — рядом с mirrors профиля (слот изолирован), одна папка = один sha. `paths.js` резолвит путь по текущему
  sha репозитория; `indexCompatibility()` (repo id + revision + schema) остаётся гейтом.
  Потребители индекса (`indexed-repo.js`, `prepare_task`) меняются **только в точке резолва пути** (один шов).
- L1 — детерминированный рендер из индекса: сигнатуры + первая строка doc-комментария, ранжирование по
  числу входящих ссылок (идея Aider, не код) + буст `focus`; байт-в-байт на том же sha.
- L0 — агрегация модулей/точек входа под бюджет ≤ 2k токенов (детерминированный оценщик токенов,
  обрезка с честной пометкой «опущено N»), однострочные описания модулей — дешёвая LLM через собственный
  `fetch` к OpenRouter (`src/repo-map/llm.js`, без зависимостей от ядра; ключ `OPENROUTER_API_KEY`),
  кеш `descriptions.json` по хешу содержимого модуля. Без ключа/ошибки → структура без описаний.
- Триггеры: (а) `hooks.afterSpawn` в `src/workspace/workspace.js` — фоновая сборка для baseRevision, спавн не
  блокируется, статус в `engineering_workspace_status`; (б) ленивая достройка при первом `repo_map` на новом
  sha (покрывает «после мержа в main» без вебхука); (в) lock-файл по sha для параллельных сборок;
  retention — держать N=10 последних sha, чистка при новой сборке.
- Fолбэк: любая проблема (нет карты, building, failed, чужой sha) → явный статус + «читай сырой репо»;
  raw-repo путь не трогаем. Тул никогда не возвращает пустой ответ (conformance).

**Почему не проще.** «Просто отдать сырой индекс» = 300k токенов — не про бюджет. «Свой парсер с нуля» —
больше кода, чем вендор одного файла. «Отдельный генератор вместо индекса» — второй сканер того же репо.
«Сборка в вебхуке мержа» — новый внешний триггер; ленивая достройка закрывает ту же ценность без него.

**Затронутые файлы/модули:**
- Новое: `src/repo-map/{paths,build,l0,l1,llm,status}.js`, `src/mcp-skills/tools/35-repo-map.js`,
  `vendor/acorn/{acorn.js,LICENSE}`, `scripts/sandbox/repo-map.mjs`.
- Изменяемые: `src/index/schema.js` (резолв пути кеша), `src/index/build.js` (выход в заданный каталог),
  `src/index/status.js` (та же логика для нового layout), `src/index/lang.js` (пробел CJS),
  `src/context-sources/indexed-repo.js` + `src/prepare-task.js` (резолв пути — один шов),
  `src/workspace/workspace.js` (хук), `src/workspace/for-task.js` (ensureMirror → та же точка),
  `src/mcp-skills/tools/30-repo-context.js` (только если использует путь индекса), `provider-manifest.json`,
  `playbooks-src/feature.json`, `playbooks-src/debugging.json`, `src/prompt-domains/engineering.md`,
  `library/step-types.json` (notes шага), `package.json` (check/тесты), `docs/INDEXER.md`.

## 4. Срезы (порядок, каждый со своим тестом)

1. **Кеш-хранилище.** `repo-map/paths.js` + перевод выхода индекса в `<workspacesRoot>/repo-maps/<repoId>/<sha>/`,
   обновить `indexed-repo.js`/`prepare_task` (один шов), retention N=10, lock по sha.
   Тест: две рабочие копии одного sha → один кеш; чужой sha/schema → игнорируется; параллельные сборки → одна.
   *(расширяет `tests/indexer.test.js`)*
2. **Парсер.** Вендор acorn + правка `lang.js` (CJS `module.exports`, методы).
   Тест: фикстура в стиле trained-assist-agent (CJS) → символы не пропущены; байт-в-байт стабильность.
3. **L1-рендер.** `repo-map/l1.js`: скелет, ранжирование, focus-буст, шапка с числом опущенного.
   Тест: снапшот на фикстуре; focus поднимает файл наверх; повтор = байт-в-байт.
4. **L0-рендер.** `repo-map/l0.js`: агрегация модулей под бюджет ≤ 2k (оценщик токенов), шапка (sha, опущено,
   как взять L1), точки входа/тесты/конфиг. Тест: бюджет на фикстуре и на реальном репо агента; пустой репо.
5. **LLM-описания.** `repo-map/llm.js`: fetch к OpenRouter, кеш по хешу модуля, деградация без ключа/при ошибке.
   Тест: мок fetch (без сети); без ключа → L0 собирается без описаний.
6. **MCP-тул.** `35-repo-map.js` + `provider-manifest.json` + conformance. Тест: `tests/mcp-empty-result.test.js`
   (никогда пусто; building/failed → явный статус).
7. **Триггеры.** Хук `afterSpawn` (фон, спавн не замедляется — измеримо), ленивая достройка в тулe,
   статус в `engineering_workspace_status`. Тест: `tests/workspace.test.js` (хук вызван, спавн не ждёт сборки).
8. **Правило в плейбуках.** feature/debugging (`explore-context`/`bug-context` notes), `step-types.json`,
   `src/prompt-domains/engineering.md` → `npm run build:playbooks`. Тест: `tests/playbooks.test.js` + `check:playbooks`.
9. **Песочница.** `scripts/sandbox/repo-map.mjs` — e2e-цикл по шагам сценария (fixture-repo → build → L0 → L1 →
   инвалидация), детерминированный pass/fail. Тест — сам (см. §5).

## 5. План проверки (шаг сценария → проверка, уровень S)

| Шаг сценария | Проверка | Уровень |
|---|---|---|
| 1. Спавн строит карту в фоне | автотест хука (срез 7) + замер «спавн не ждёт» | S3 |
| 2. Новый sha main после мержа | автотест ленивой достройки (срез 7): новый sha → сборка при первом обращении | S3 |
| 3. L0 < 1 с, ≤ 2k токенов | автотест бюджета (срез 4) + замер времени из кеша в песочнице | S5 (локально) |
| 4. L1 скелет + focus | снапшот-тесты (срез 3) | S3 |
| 5. Точечное чтение вместо grep | A/B-бенч на 10 прошлых задачах (приёмка эпика) — ручной прогон в deliver, чек-лист в issue | S2 |
| 6. Правило в плейбуках | `tests/playbooks.test.js`, `npm run check:playbooks` (срез 8) | S3 |
| 7. PR-ветка: main + дельта | автотест: на ветке с коммитом шапка содержит дельту (срез 6) | S3 |

Целевая песочница: **S5**, одна команда `node scripts/sandbox/repo-map.mjs` (~1–2 мин), детерминированный
pass/fail: фикстура-репо → карта собирается → L0 в бюджете → L1 байт-в-байт → чужой sha игнорируется →
без ключа LLM структура есть → инвалидация по новому sha работает. LLM в песочнице мокается (без сети).
Сначала прогон ДО изменений — падает «модуля/тула нет» (правильная причина).

## 6. Риски и откат

- **Сломать существующих потребителей индекса** (prepare_task/repo_context): риск средний.
  Откат: revert PR целиком (мерж одной ветки); кеш — производный, удаление папки безопасно; данные не теряются,
  старые индексы в `.engineering/index` остаются на диске и читаются прежним кодом до отката.
- **Спавн замедлится/упадёт из-за хука**: хук только планирует фоновую задачу и никогда не роняет спавн
  (try/catch + лог); kill-switch `REPO_MAP_SPAWN_BUILD=0` (env) — мгновенное отключение без откода.
- **Acorn не разбирает TS**: задумано — TS идёт regex-путём; не регрессия относительно v1.
- **LLM-стоимость/доступность**: описания кешируются по хешу модуля, без ключа — структура; L1 не зависит от LLM.
- **Устаревание карты**: гейт по sha не даёт отдать чужой sha; retention чистит старые.
- **Миграция данных**: не нужна (всё производное). Возврат к старому расположению индекса — тоже revert,
  двойного письма не будет.
- **ДвухVM-дублирование кеша**: принято как риск (см. сценарий), не чиним.
